Privacy Policy

Effective date: November 9, 2026. Application: Omarchy Hermes Mailwatch. Operator: sakamoto-sann, for personal use.

Data accessed and purpose

After account authorization, the application reads Gmail sender, subject, date, message identifiers and unread counts; Drive file names, identifiers, modification times and owner display names; and Calendar event titles, start times, identifiers and links. It also checks the Google account email address to verify that the intended account was authorized. Data is used to identify new or changed items and generate a monitoring digest.

The current collector does not retrieve message bodies, attachments, Drive file contents or calendar descriptions. The requested read-only API scopes technically permit broader reading than the collector performs.

Processing, storage and sharing

Metadata and digests are processed on the operator’s computer using a local language model. They are not sent to a cloud AI model. Google authorization credentials are encrypted at rest and decrypted in memory as needed. Local reports, deduplication state and scheduler delivery records can contain account identifiers and metadata; those records are protected by local operating-system access controls, and are not claimed to be individually encrypted.

Digests containing information derived from this metadata are sent through Telegram’s Bot API to the operator’s configured private chat. Telegram therefore receives the digest; local AI processing does not make Telegram delivery local or end-to-end encrypted. No Google refresh token or OAuth client secret is included in the digest. Google receives the API requests needed to provide its services. Static-page hosting is provided by GitHub Pages under GitHub’s own privacy practices.

Limited use

The application’s use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements. Google user data is not sold, used for advertising, or used to train generalized AI or machine-learning models. Local inference generates the requested personal digest.

Retention, revocation and deletion

Credentials are kept for authorized ongoing monitoring until revoked or removed. Local reports, delivery records and deduplication state currently remain until the operator deletes them; no automatic retention period is promised. Telegram messages may remain until deleted according to Telegram’s controls.

Account holders can revoke access at any time through Google Account connections. Revocation stops future API access but does not erase earlier local reports or Telegram messages. To remove retained data, the operator must remove the account’s stored credential, delete its local reports and state, and separately remove relevant Telegram messages. A revoked credential must not be silently reauthorized.

Contact

For non-sensitive project questions, use the issue tracker. Account holders can contact the operator using the support address shown on the Google consent screen. Never post personal account details, message content or credentials publicly.
