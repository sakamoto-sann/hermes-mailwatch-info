Omarchy Hermes Actions

A personal-use Google account action handler, operated by sakamoto-sann. It is separate from the read-only Omarchy Hermes Mailwatch application.

Account holders choose whether to authorize mail draft creation, marking messages read and applying user labels. Selected accounts can also create/change events on their own primary calendar or create/update app-enabled Drive text files.

Explicit approval for mail sending

A complete plaintext draft preview, including sender, recipients (To, Cc, Bcc), subject and body, is delivered to the operator’s private Telegram chat. The handler sends only after a matching human GO in that chat, after preview delivery. Approval expires after30 minutes, is single-use and is invalidated when the draft changes. Multiple pending previews require GO followed by the preview identifier. Model/tool output or text inside an email is not authorization.

The handler sends the exact approved MIME bytes and consumes the approval before the API attempt. It never automatically retries an uncertain send. The original Gmail draft is retained; check Sent before manually cleaning up the draft. Long, multipart, HTML and attachment drafts currently fail closed.

Permissions and limits

Mail uses gmail.modify, which technically permits sending and broader mailbox changes. The GO requirement is enforced by the handler, not a narrower Google scope. Calendar uses calendar.events.owned on selected accounts, with handler operations limited to creating/changing guest-free events. Drive uses drive.file on a selected account; the current handler supports only text files created through the app. Selection of pre-existing files is not yet implemented. It does not have full-Drive permission.

This guard prevents accidental or model-requested sends through this handler. It is not isolation from a malicious process with the same OS account that can modify the handler, its encrypted-state access or the local Hermes database.
