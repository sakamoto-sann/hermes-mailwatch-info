Privacy — Omarchy Hermes Actions

Privacy Policy

Effective November9, 2026. Operator: sakamoto-sann, for personal use.

This app is distinct from the read-only monitor. Google account email addresses identify the authorized account. Gmail draft headers and body are read to show the complete draft and bind approval to its content; authorized drafts may be created and, after explicit approval, sent. Message identifiers and user label identifiers are used for read/label updates. Selected Calendar accounts provide event identifiers, titles, descriptions, locations and times for creating/changing events. The selected Drive account provides names, identifiers and text of app-enabled files.

The OAuth scopes technically allow broader Gmail operations, deletion of owned calendar events, and deletion of app-enabled Drive files. The current handler exposes neither mail deletion, event deletion, file deletion nor sharing/permission changes. It performs no cloud AI calls itself.

OAuth client credentials, refresh tokens and approval state are encrypted at rest using user-scoped operating-system encryption. They are decrypted in process memory for API requests and never supplied to the language model by this handler. Approval state stores identifiers, timestamps and hashes, not a plaintext mail body. The local Hermes database is read to verify the operator’s platform-tagged GO. Operating-system access controls protect this database; same-UID process isolation is not claimed.

Draft previews are sent to the operator’s configured private Telegram chat through Telegram’s Bot API. Telegram receives the full preview. This delivery is not local or end-to-end encrypted. Sent messages and edited content are transmitted to Google and, in the case of sent mail, to the user-approved recipients. Google and Telegram retain their own records under their policies. Hermes delivery/session records may retain previews locally. GitHub Pages hosts this public information.

The app’s use and transfer of Google API data adheres to the Google API Services User Data Policy, including Limited Use. Google user data is not sold, used for advertising, or used to train generalized AI models.

Credentials and local state remain until removed by the operator. No automatic retention period for reports or chat history is promised. Approval eligibility expires after30 minutes, but the audit record may remain. Revoke access at Google Account connections. Revocation blocks future API access without deleting earlier drafts, sent mail, local records or Telegram messages. Remove those separately using the relevant service controls. Requests to remove local data can be sent to the operator through the support contact shown by Google. Never post private data or credentials in the public issue tracker.
